# أنيرا — Native Android (v0.1.0-foundation)

## شو موجود فعلاً هلق
مشروع أندرويد حقيقي (Gradle + Kotlin + Jetpack Compose + Room) يُبنى فعلياً عبر
GitHub Actions وينتج APK قابل للتنزيل. شاشة واحدة تأسيسية تثبت أن كامل السلسلة
تعمل من طرف لطرف: تقرأ فعلياً من قاعدة بيانات Room حقيقية.

**هذا ليس تطبيق أنيرا الكامل.** هو أساس (foundation) مبني بعناية ومُتحقَّق منه
هيكلياً، لكن الشاشات والمنطق الفعلي (نموذج التسجيل، قوائم السجلات، الأرشيف،
كشف التكرار، تصدير Excel/PDF، تكامل تيليجرام) غير مبنية بعد.

## ليه هيك بالضبط
ترجمة تطبيق أنيرا كامل (840+ سطر JS، منطق دمج/أرشفة معقّد اتصلّح فيه أكتر من
باگ حقيقي بجلسات سابقة، محرك ضغط يدوي، تصدير Excel/PDF...) لكوتلن دفعة وحدة
وبلا اختبار = مخاطرة عالية جداً على مشروع بيتعامل مع بيانات هوية حقيقية لأشخاص
ضعفاء. الأصح: بناء تدريجي، كل جزء يُختبر فعلياً (عبر بناء CI حقيقي، لأنه ما
عندي بيئة تصريف Kotlin/Gradle محلياً لأتحقق منها قبل ما توصلك) قبل ما ننتقل
للي بعده — بالضبط نفس فلسفة "شات واحد، لا تراكم أخطاء" المعتمدة بمشروع الويب.

## القرارات التقنية المتخذة
- **minSdk 26** (بدل 24): يسمح بأيقونة adaptive-icon بصيغة XML بحتة بدون
  الحاجة لملفات PNG احتياطية.
- **بلا `gradlew`**: البناء يعتمد كلياً على GitHub Actions (`gradle/actions/setup-gradle`)
  الذي يهيّئ Gradle تلقائياً — أنت لا تحتاج أي شي محلياً على الهاتف.
- **صلاحية واحدة فقط**: `INTERNET` (لتيليجرام حصراً). `allowBackup=false` عمداً
  لحماية بيانات الهوية من النسخ التلقائي لحساب جوجل.
- **جدول واحد بدل بنية متداخلة**: بالويب الأرشيف مصفوفة كائنات منفصلة؛ هنا
  جدول `records` واحد بعمود `monthKey` — أبسط وأصح لقاعدة علائقية، ونفس منطق
  التوجيه المُصلَح بنسخة الويب (حسب توقيت السجل نفسه، لا حسب وجود أرشيف محلي).
